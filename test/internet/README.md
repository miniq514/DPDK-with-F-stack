# dac 链路 IPv6 联调（8004 发端）

本目录用于 **8004 ↔ 8007 万兆 DAC 直连** 的内核态 IPv6 配网与 ping 互通测试。  
8004 是 **发端**，8007 是 **收端**；两台机器网卡名相同，但 **IP 不同**。

---

## 拓扑（一眼看懂）

```
  8004 (发端)                         8007 (收端)
  enp66s0f1  ──── DAC 铜缆 5m ────  enp66s0f1
  …:0003/64                          …:0002/64
```

| 项目 | 8004（本机） | 8007（对端） |
|------|--------------|--------------|
| 角色 | **发端** | **收端** |
| 网卡 | `enp66s0f1` | `enp66s0f1` |
| PCI | `0000:42:00.1` | `0000:42:00.1` |
| IPv6 | `1111:2222:1111:2222:1111:2222:1111:0003/64` | `1111:2222:1111:2222:1111:2222:1111:0002/64` |
| 典型 MAC | `90:e2:ba:50:7c:f9` | `90:e2:ba:50:aa:71` |

> 旧 IPv4 联调地址 `192.168.1.3`（8004）/ `192.168.1.2`（8007）**已废弃**，请改用上表 IPv6。

## 8004 上要拷什么

只需把整个 `test/internet/` 目录拷到 8004 即可（或拷完整 `Fstack-DPDk` 仓库也行）。

```
Fstack-DPDk/test/internet/
├── README.md           ← 本文
└── setup_f1_ipv6.sh    ← 一键配网脚本
```

**示例（在 8007 上打包，拷到 8004）：**

```bash
# 8007 上
cd /home/dev/HMH--8007/Fstack-DPDk
tar czf internet-ipv6.tgz test/internet/
scp internet-ipv6.tgz user@8004:/tmp/

# 8004 上
mkdir -p ~/Fstack-DPDk/test
cd ~/Fstack-DPDk/test
tar xzf /tmp/internet-ipv6.tgz
chmod +x internet/setup_f1_ipv6.sh
```

路径可按 8004 实际目录调整，下文以 `~/Fstack-DPDk/test/internet/` 为例。

## 8004 操作步骤（按顺序做）

### 1. 确认 DAC 线已插好

- 8004 的 **f1**（`enp66s0f1`）与 8007 的 **f1** 直连  
- **不要** 插 f0 光口；f0 是交换板 fibre 口，与 dac 无关

### 2. 确认 f1 未被 DPDK 占用

```bash
ip link show enp66s0f1
# 驱动应为 ixgbe，不能是 vfio-pci
```

若显示 `vfio-pci`，说明 F-Stack/DPDK 仍占着网卡，需先 release 再配 IP。

### 3. 运行配网脚本（8004 固定用参数 `8004`）

```bash
cd ~/Fstack-DPDk/test/internet
sudo ./setup_f1_ipv6.sh 8004
```

脚本会自动：

- `ip link set enp66s0f1 up`
- 清掉旧 IPv4（如 `192.168.1.3`）和旧实验 IPv6
- 绑定 `1111:2222:1111:2222:1111:2222:1111:0003/64`
- 打印网卡 MAC、链路、IP 等摘要

**期望输出要点：**

```
  角色            : 8004 (发端)
  链路            : up (Link detected: yes)
  本机 IPv6       : 1111:2222:1111:2222:1111:2222:1111:0003/64
  对端 IPv6       : 1111:2222:1111:2222:1111:2222:1111:0002/64 (8007)
```

### 4. 让 8007 也配好（对端同事或你自己 SSH 过去）

在 **8007** 上执行（参数是 `8007`，不是 `8004`）：

```bash
sudo ./test/internet/setup_f1_ipv6.sh 8007
```

## ping6 互通测试

**在 8004 上 ping 8007：**

```bash
ping6 -I enp66s0f1 -c 5 1111:2222:1111:2222:1111:2222:1111:0002
```

**在 8007 上 ping 8004（反向确认）：**

```bash
ping6 -I enp66s0f1 -c 5 1111:2222:1111:2222:1111:2222:1111:0003
```

**通过标准：** 能收到 reply，丢包率 0%（或偶发 1 包可接受，持续失败则查下面故障表）。

> **注意：** 8004 上请 ping `…:0002`（8007），**不要** ping 本机 `…:0003`。

## 手动检查命令（排错用）

```bash
# 看 f1 地址
ip -6 addr show dev enp66s0f1

# 看链路是否 up
cat /sys/class/net/enp66s0f1/carrier    # 1=有链路

# 看 ARP/NDP 邻居（ping 后应有 8007 条目）
ip -6 neigh show dev enp66s0f1

# 抓包看有没有 ICMPv6（可选）
sudo tcpdump -ni enp66s0f1 icmp6
```

## 常见问题

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 脚本报 `vfio-pci 占用` | F-Stack/DPDK 未退出 | 停掉收发包程序，把网卡还回 `ixgbe` 再跑脚本 |
| `Link detected: no` | DAC 未插牢 / 对端 f1 down | 插紧线；8007 也执行 `setup_f1_ipv6.sh 8007` |
| ping 100% 丢包 | 8007 未配 IP 或配错 | 8007 确认是 `…:0002`，不是 `…:0003` |
| ping 自己的 `…:0003` | 测错地址 | 8004 应 ping 对端 `…:0002` |
| 显示 `…:3/64` 而非 `…:0003/64` | 正常 | 内核 IPv6 压缩显示，与 `…:0003` 是同一地址 |
| 仍残留 `192.168.1.x` | 旧配置 | 再跑一次 `setup_f1_ipv6.sh 8004` 会自动清理 |

## 与后续打流的关系

本 README 只做 **内核态 IPv6 + ping6**，用于确认 DAC 物理链路和地址规划正确。

后续 **pktgen 发流 / F-Stack 收包** 会走用户态 DPDK，运行时内核看不到 f1 上的 IP，属正常现象；打流前需按 `docs/README.md` 把网卡交给 vfio。  
**顺序建议：** 先本目录 ping 通 → 再切 DPDK/F-Stack 联调。
