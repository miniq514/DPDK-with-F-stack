## 缺口与可选下一步（供决策）

按「投入 / 收益」粗分，**不是必须按序做**：

| 优先级建议 | 方向 | 解决什么 | 难度 |
|------------|------|----------|------|
| A | **TCP 发端抬速**（发端开 HW csum/TSO，或确认单核软 csum 上限） | 把 ~3G 再往上推，看收端何时先丢 | 中 |
| B | **TCP 多五元组 + RSS 收端多核**（路由器可区分五元组） | 单流墙之外按连接横扩；需对称 RSS / SO_REUSEPORT | 中～高 |
| C | **稳定多连接打流**（内核多进程发，或修 F-Stack MP 客户端 RSS） | 为 B 提供可复现发端 | 中～高 |
| D | **KNI + 业务同开 soak** | 运维口与 8888 打流长期共存 | 低～中 |
| E | **fibre 端到端** | 交换板真实业务路径 | 依赖硬件 |
| F | **半旁路再抠 / V4.0** | UDP 从 ~9.4G → ~9.8G | 中 |
| G | **工程化**（`--bind-ip`、配置统一、CI 冒烟） | 降低换机/联调成本 | 低 |

**若目标是「先把 TCP 数字说清楚」→ 选 A 或 B/C。**  
**若目标是「上线可运维」→ 选 D。**  
**若目标是「UDP 逼近线速」→ 选 F（半旁路已验证方向）。**

## 风险与依赖

| 风险 | 缓解 |
|------|------|
| F-Stack 单核 UDP 栈路径 ~6G | `--udp-bypass` 线速 ~9.4G；再抠见 V4.0 |
| TCP 单流发端 ~3G（软 csum + 无 TSO） | 发端 offload 试验；勿与 pktgen 10G 横比 |
| TCP 单流收端同核墙 | 多连接 + NIC RSS → 多队列/多进程（五元组可区分时） |
| F-Stack 多进程 TCP 客户端握手不稳 | 暂用单进程或内核多进程发端；收端 SO_REUSEPORT 更成熟 |
| 8004 无 `iommu=pt` | `setup_env.sh` 运行时切 IOMMU identity |
| fibre 依赖交换板 | 仅 8007 f0 |
