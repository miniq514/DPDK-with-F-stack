# 性能统计

按版本记录 Fstack-DPDk 收端实测数据。吞吐口径：`Throughput (burst, payload)` — 首包 submit 至末包 submit 窗口内的 payload 比特率。

**测试环境（V1.0.1 共通）**

| 项目 | 值 |
|------|-----|
| 收端 | 8004，`enp66s0f1` / `0000:42:00.1`，82599ES |
| 发端 | 8007 pktgen，`uio_pci_generic` |
| 链路 | dac IPv6 直连 |
| Payload | raw 1344B / 包（8B 头 + 1336B 体） |
| 帧长约 | 1400B wire |
| 收端栈 | F-Stack 单 lcore（`lcore_mask=1`）+ pthread writer |
| DPDK 驱动 | 收端 `igb_uio` + IOMMU identity；发端 `uio_pci_generic` |

## V1.0.1

**状态：** 已验证 dac 双向互通；8004 作收端达标。

### 功能验收

| 场景 | 包数 | 线路速率 | 结果 | 备注 |
|------|------|----------|------|------|
| 冒烟 | 100 | 不限速 | COMPLETE | seq_gaps=0 |
| 反向 dac | 1000 | 不限速 | COMPLETE | 8007 发 → 8004 收 |
| 压测 | 1e5 | 6 Gbps | COMPLETE | 100001/100000 |
| 压测 | 2e6 | 6 Gbps | COMPLETE | 2000013~2000015/2000000，2.6GB |
| 压测 | 2e6 | 7 Gbps | **INCOMPLETE** | 1796084/2000000（10.2% 丢包） |
| 压测 | 2e6 | 10 Gbps | 大量丢包 | 超出协议栈处理能力 |

### 6 Gbps · 2e6 详细数据（代表性达标用例）

| 指标 | 值 |
|------|-----|
| matched / expected | **2000015 / 2000000** |
| Total RX | 2000015 |
| Buffer drops | 0 |
| Ring full drops | 0 |
| Ring enqueue waits / spins | 0 / 0 |
| Buffer pool peak | 163 / 16384（≈1%） |
| Burst 时长 | 3.816 s |

### 7 Gbps · 2e6 对比（超限用例）

| 指标 | 6 Gbps | 7 Gbps |
|------|--------|--------|
| matched | 2000015 | 1796084 |
| 丢包率 | 0%（含发端余量） | **10.2%** |
| Buffer drops | 0 | 0 |
| Burst 吞吐 | 5635 Mbps / 524 Kpps | 5901 Mbps / 549 Kpps |
| Buffer pool peak | 163 | 198 |

> 7 Gbps 丢包时应用层计数器仍全零——丢包发生在 **DPDK/网卡 RX 环**（`rte_eth_rx_burst` 来不及取走），非应用 ring 溢出。

### 性能上限结论（V1.0.1）

| 指标 | F-Stack 收端（本工程） | UDP_DPDK 对照（同硬件） |
|------|------------------------|-------------------------|
| 可持续线速 | **~6 Gbps / ~524 Kpps** | **~9.8 Gbps 线速**（O_DIRECT） |
| 7 Gbps | 丢包 ~10% | 视配置可达 COMPLETE |
| 10 Gbps | 大量 DPDK 层丢包 | 可达 COMPLETE |
| 瓶颈位置 | F-Stack 单核协议栈处理 | 磁盘/写盘（解耦后） |

**关键特征：**

- 6 Gbps 下 2M 包长稳态测试 buffer peak 仅 1%，**非缓冲掩盖**，是处理速率与入向速率基本平衡。
- 超过 ~6 Gbps 后，入向包率高于 `ff_recvfrom` 消费速率，512 描述符 RX 环溢出导致 `imissed`。
- 发端 pktgen pcap 循环存在尾部截断，已通过发端余量（`count/1000+64`）修复；与收端性能无关。

## V1.1（UDP · ZC recv / 半旁路）

**状态：** 已实测（2026-07-13）；半旁路抬高 UDP 收端上限；`ff_zc_recv` 无实质收益。

**环境增量：** 单五元组（发端不能 RSS 分流）；`count=1e6`；payload raw 1344B。

### `ff_zc_recv`（`--zc-recv`）

仍走完整 UDP→PCB→sockbuf，仅少一次 `soreceive→uiomove`；落盘路径仍 memcpy 入 cpbuf。

| 目标 | 模式 | 结果 | burst payload |
|------|------|------|---------------|
| 6 Gbps | `recvfrom` | COMPLETE | 5624 Mbps |
| 6 Gbps | `ff_zc_recv` | COMPLETE | 5636 Mbps（~+0.2%，噪声级） |

**结论：** 单流场景 ZC 收不值得当主优化；墙在栈，不在用户态那次拷贝。

### 半旁路（`--udp-bypass`）

`ff_regist_packet_dispatcher` 在入 `ff_veth`/协议栈前解析 Eth+IPv6/IPv4+UDP（风格对齐 `UDP_DPDK`）；命中 `dst_port` 则直接入应用 ring 并吞掉 mbuf；ND 等非目标流量仍回原 queue 走栈。无 socket / sockbuf。

| 目标 | 模式 | 结果 | burst payload |
|------|------|------|---------------|
| 6 Gbps | socket | COMPLETE | 5634 Mbps |
| 6 Gbps | bypass | COMPLETE | 5640 Mbps（发端未打满，无差异） |
| 9 Gbps | socket | **INCOMPLETE** 689768/1e6 | **5798 Mbps**（栈墙） |
| 9 Gbps | bypass | **COMPLETE** 1e6/1e6 | **8461 Mbps / 787 Kpps** |
| **线速**（`--rate 100`） | bypass | **COMPLETE** 1e6/1e6 | **9395 Mbps / 874 Kpps** |

**线速档缓冲承压（1e6）：** Buffer/Ring drops=0，enqueue waits/spins=0，**bufpool peak 2003/16384（~12%）** — 有在途、未打满；非写盘侧顶满。

**结论：**

| 指标 | socket（V1.0.1） | `--udp-bypass`（V1.1） |
|------|------------------|------------------------|
| 高压可收满 | ~6 Gbps | 9G 目标 **~8.5G**；线速 **~9.4G** |
| 相对提升 | — | 约 **+46%**（9G）～逼近 UDP_DPDK |
| vs UDP_DPDK ~9.8G | 仍有差距 | 差 F-Stack 外壳 / 单核解析等 |

日志：`test/output/udp_zc_*`、`test/output/udp_bp_*`、`udp_bp_bypass_unc1e6_*`。入口：`run_recv.sh --udp-bypass`（与 `--zc-recv` 互斥）。

## V2.2（TCP · 多进程发端实验）

**状态：** 代码与脚本已合入；**握手不稳定**，不作正式性能基线（2026-07-13）。

| 项目 | 值 |
|------|-----|
| 发端 | `scripts/run_tcp_fstack_send_mp.sh`（primary/secondary，每进程一连接，1344B） |
| 收端 | `--traffic-only --max-conns N`（多连接、只计流量、不落盘） |
| 现象 | 常仅 1 条连接成功（~3.6G）；偶发 2 条合计 ~4.3G；其余 `connect timeout` |
| 根因判断 | F-Stack 多进程下 SYN-ACK 的 RSS/队列归属；见 [错误日志及改进.md](./错误日志及改进.md) §22 |

**结论：** 多连接抬 TCP 吞吐这条路**方向成立**，但 F-Stack MP **客户端**尚未可复现交付。稳定方案待选：修跨进程分发，或改内核多进程发端。
